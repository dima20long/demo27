## 2. Результаты проверки

### Структура проекта
Изучена структура проекта, основные модули, представления (Views), сервисы (Services), модели и тесты. Подготовлена карта проекта и чек-лист проверки.

### Стиль кода
Проведен анализ с помощью Flake8.

Выявлены замечания:
- длинные строки (E501);
- лишние пустые строки (E303);
- пробелы в пустых строках (W293);
- неиспользуемые импорты (F401);
- пробелы в конце строк (W291).

### Логика приложения
В ходе проверки выявлены потенциальные проблемы:
- отсутствие обработки некорректных дат в отдельных API-обработчиках;
- некорректные позиции заказа могут пропускаться без явного сообщения об ошибке;
- отсутствует ограничение скидки сверху (100%), что может привести к отрицательной сумме позиции;
- генерация номеров заказов на основе максимального существующего номера может быть небезопасной при параллельном создании заказов;
- повторяющиеся запросы к БД при получении связанных данных могут снижать производительность.

### Безопасность
- Проверены обработчики авторизации и административные маршруты.
- Проверены основные механизмы валидации входных данных.
- Проверены файлы зависимостей и признаки наличия секретов в отслеживаемых именах файлов.
- Полный аудит зависимостей не выполнен: pip_audit отсутствует в окружении.
- Необходима дополнительная проверка прав при регистрации и назначении ролей.

### Тестирование
Команда:
python -m pytest

Результат:
14 passed in 13.24s

Все имеющиеся тесты успешно пройдены.

Покрыены тестами:
- авторизация;
- заметки (Notes).

Необходимо расширить тестирование:
- заказов продаж;
- производственных заказов;
- расчётов стоимости;
- скидок;
- обработки некорректных входных данных.

## 3. Основные рекомендации

1. Добавить валидацию скидки в диапазоне 0–100%.
2. Обрабатывать ошибки преобразования даты и числовых значений.
3. Не пропускать некорректные позиции заказов без уведомления.
4. Добавить тесты для API заказов и расчётов.
5. Проверить назначение ролей при регистрации пользователей.
6. Оптимизировать повторяющиеся запросы к базе данных.
7. Провести аудит зависимостей с помощью pip_audit.
8. Устранить замечания Flake8.
