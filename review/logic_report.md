# Отчёт по логике и API

## L-01 — API CRUD маршруты не защищены авторизацией (High)
- Файл: `app/views/base_view.py`; конкретные маршруты регистрируются в `app/__init__.py` и `app/views/*_view.py`.
- `BaseAPIView.decorators = []`, то есть по умолчанию нет login_required.
- Проверка авторизации/роли обнаружена в admin views, но не обнаружена в обычных API views clients, products, materials, operations, specifications, sales-orders, production-orders.
- Следствие: API может быть доступен анонимному клиенту для чтения и/или создания/изменения/удаления бизнес-данных, если маршрут реализует соответствующий HTTP-метод.
- Рекомендация: установить `login_required` на все API CRUD views; дополнительно проверять роль/права на изменяющие операции. Проверить доступ тестами без сессии.

## L-02 — Публичное чтение заметок
- Файл: `app/views/note_view.py`, GET `/api/notes/` и GET `/api/notes/<note_id>`.
- Декоратор авторизации не установлен. API возвращает содержимое заметок и логин автора.
- Рекомендация: если заметки должны быть внутренними, требовать авторизацию и ограничивать доступ по владельцу/роли.

## L-03 — CAPTCHA фактически не проверяется на веб-логине
- Файл: `app/blueprints/web.py`, функция `login_page()`.
- `captcha_ok = True` и комментарий «Временно отключена проверка капчи»; блок отказа никогда не выполняется.
- Рекомендация: интегрировать проверку результата puzzle captcha либо удалить CAPTCHA UI, если механизм не используется, и не считать её защитой.

## L-04 — Валидация входных данных неоднородна
- По API обработчикам проверяется наличие отдельных полей, но в некоторых endpoints нет явной проверки типов/длины/диапазонов до передачи сервисам/ORM.
- Рекомендация: DTO/schema validation (например, централизованный валидатор), ограничения длины, форматов UUID, количества, цены, дат и статусов; тесты boundary cases.

## L-05 — обработка ошибок
- Некоторые endpoints оборачивают запросы в `try/except Exception`, откатывают транзакцию и возвращают общий текст; это не раскрывает подробности клиенту, но журналирование исключений в отдельных обработчиках не видно.
- Рекомендация: логировать исключения серверной стороне с traceback и correlation id, клиенту возвращать безопасный общий ответ.

## L-06 — блокировка пользователя
- API/WEB login увеличивает `failed_attempts` и блокирует пользователя после трёх неудачных попыток; успешный вход сбрасывает счётчик.
- В коде нет автоматического времени разблокировки; блокировка снимается административным действием. Уточнить, соответствует ли это требованию, и протестировать одинаковое поведение web/API.

## Проверки
- Синтаксическая компиляция Python успешна.
- pytest не смог собрать тесты в текущей среде: отсутствует Flask (`ModuleNotFoundError: No module named 'flask'`). Это ограничение среды ревью, а не доказательство ошибок тестов.
