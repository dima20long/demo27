# День 4 — Проверка безопасности и зависимостей

## Проект
Demo27 — веб-приложение на Flask.

## Цель проверки
Провести базовый анализ безопасности проекта, проверить наличие потенциально раскрытых секретов, оценить зависимости и определить необходимость дополнительных проверок.

## 1. Проверка секретов в репозитории

**Результат:** явных совпадений не обнаружено.

Выполнен поиск отслеживаемых Git-файлов по именам, содержащим признаки секретов, паролей, учётных данных, а также файлов `.pem` и `.key`.

Совпадений не обнаружено.

**Ограничение:** проверка по именам файлов не гарантирует отсутствия секретов непосредственно в исходном коде.

## 2. Проверка конфигурационных файлов

**Результат:** в корне проекта не обнаружены очевидные файлы конфигурации и `.env`.

Проверены имена файлов, связанные с конфигурацией, окружением, Docker и зависимостями.

В корне проекта обнаружены:
- `.gitignore`
- `requirements.txt`

Дополнительная проверка конфигурации и переменных окружения необходима.

## 3. Проверка зависимостей

В проекте используются следующие библиотеки:

- Flask
- Flask-SQLAlchemy
- Flask-Login
- Flask-Migrate
- Werkzeug
- Pillow
- psycopg2-binary
- python-dotenv
- Alembic

Версии библиотек указаны с использованием минимальных ограничений (`>=`).

**Замечание:** версии зависимостей не закреплены строго, что может привести к установке более новых версий при повторной настройке проекта.

**Рекомендация:** рассмотреть закрепление версий и использование файла с точными версиями зависимостей.

## 4. Автоматическая проверка уязвимостей

Проверка с помощью `pip_audit` не выполнена, поскольку данный инструмент отсутствует в текущем окружении Python.

Наличие известных уязвимостей в установленных зависимостях не подтверждено и не опровергнуто.

**Рекомендация:** выполнить автоматическую проверку зависимостей при наличии соответствующего инструмента.

## 5. Рекомендации

- Проверить исходный код на наличие секретов и паролей.
- Убедиться, что чувствительные данные хранятся в переменных окружения.
- Проверить настройки Flask и режим отладки.
- Закрепить версии зависимостей.
- Провести автоматическую проверку библиотек на известные уязвимости.
- Убедиться, что `.env` и другие файлы с секретами исключены из Git.

## Итог

В ходе базовой проверки явных совпадений с именами секретных файлов среди отслеживаемых Git-файлов не обнаружено.

Зависимости проекта определены в `requirements.txt`, однако версии не закреплены строго.

Полноценная проверка уязвимостей зависимостей не проводилась, поскольку инструмент `pip_audit` отсутствует.

Проверка безопасности является предварительной и требует дальнейшего анализа конфигурации и исходного кода.
