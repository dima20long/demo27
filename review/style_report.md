# Отчёт по стилю и качеству кода

## Проведённые статические проверки
- Архив содержит 67 Python-файлов.
- Все 67 файлов успешно прошли синтаксическую компиляцию `py_compile` (ошибок синтаксиса не обнаружено).
- В подсчёте по Python-файлам выявлено 84 строки с trailing whitespace и 112 строк длиннее 88 символов. Эти подсчёты — простой скриптовый анализ, не полноценный запуск PEP 8 линтера.
- `flake8` и `pylint` в текущей среде отсутствуют, поэтому отчёты этих инструментов не получены.

## Замечания
### S-01 — повторный вызов `request.get_json()` в регистрации
- Файл: `app/blueprints/auth.py`, функция `register()`, строки 102–103 (по архиву).
- Один и тот же JSON повторно читается без использования результата второго вызова.
- Рекомендация: удалить повторный вызов.

### S-02 — форматирование и длинные строки
- В Python-коде заметны длинные строки, trailing whitespace, а также некоторые плотные выражения/условия.
- Рекомендация: применить форматирование (например, Ruff/Black) и затем проверять lint, но не менять стиль всего проекта автоматически без согласования.

### S-03 — дублирование API-реализаций
- В проекте одновременно имеются `app/blueprints/` (function-based) и `app/views/` (class-based).
- В фабрике `app/__init__.py` зарегистрированы маршруты из `app/views/`, а function-based модули `app/blueprints/` также содержат CRUD-логику.
- Это увеличивает риск, что исправление внесут в неактивный модуль, а действующий endpoint останется прежним.
- Рекомендация: документировать активную реализацию и удалить/архивировать неиспользуемые модули только после подтверждения их отсутствия в использовании.

## Результат
Синтаксических ошибок Python не выявлено. Стилевые замечания есть; автоматическая оценка flake8/pylint не выполнена.
