## 1. Структура и архитектура
- [ ] Понятное разделение web/API, views, services, repositories, DTO, models.
- [ ] Нет неиспользуемых или дублирующих модулей.
- [ ] Нет циклических импортов.
- [ ] Конфигурация окружений используется ожидаемо.

## 2. Стиль и читаемость
- [ ] PEP 8 (импорты, отступы, длина строк, пробелы).
- [ ] Нет повторяющегося кода и лишних вызовов.
- [ ] Имена переменных, функций и классов понятны.
- [ ] Функции и классы имеют необходимые docstrings.
- [ ] Нет временного или отладочного кода.

## 3. API и бизнес-логика
- [ ] Проверка обязательных полей и типов.
- [ ] Нормализация строк и проверка границ значений.
- [ ] Корректные HTTP-коды (400, 401, 403, 404, 409, 500).
- [ ] Ошибки БД корректно обрабатываются.
- [ ] Пагинация имеет ограничения.
- [ ] Цена, количество, даты и статусы проверяются.
- [ ] Нет неконтролируемого доступа к чужим данным.

## 4. База данных
- [ ] ORM-запросы проверены.
- [ ] Foreign keys, cascade, unique и check constraints соответствуют логике.
- [ ] Проверена возможность отрицательных цен и количеств.
- [ ] Схема БД соответствует моделям приложения.
- [ ] Удаление записей не нарушает целостность данных.
- [ ] Транзакции и откаты работают корректно.

## 5. Безопасность
- [ ] Авторизация API и проверка ролей на сервере.
- [ ] Регистрация не позволяет назначать привилегированные роли самостоятельно.
- [ ] CAPTCHA действительно проверяется сервером.
- [ ] Секреты и пароли не хранятся в репозитории.
- [ ] DEBUG выключен в production.
- [ ] XSS: пользовательские данные выводятся безопасно.
- [ ] CSRF-защита для cookie/session и изменяющих запросов.
- [ ] CORS ограничен доверенными источниками.
- [ ] Ошибки не раскрывают внутренние данные.

## 6. Frontend
- [ ] Ошибки API отображаются корректно.
- [ ] HTML/JS безопасно обрабатывает пользовательские данные.
- [ ] Проверено использование innerHTML и inline handlers.
- [ ] Обработчики событий корректно работают при отсутствии элементов или данных.
- [ ] Формы проверяют входные данные.

## 7. Тестирование
- [ ] Тесты запускаются на отдельной тестовой БД.
- [ ] Есть позитивные и негативные тесты авторизации.
- [ ] Проверены регистрация и блокировка пользователя.
- [ ] Проверены права анонимного, обычного пользователя и администратора.
- [ ] Проверены CRUD-операции.
- [ ] Есть тесты XSS payload, некорректных данных и граничных значений.
- [ ] Результаты pytest и линтера записаны только после фактического запуска.

## 8. Приоритет дефектов
- Critical — компрометация системы или критических данных.
- High — несанкционированный доступ или существенное нарушение безопасности.
- Medium — существенная ошибка логики или ограниченная эксплуатационная проблема.
- Low — стиль, дублирование и поддерживаемость.
